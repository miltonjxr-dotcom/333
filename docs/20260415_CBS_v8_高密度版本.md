## 〇、优化逻辑说明（给老板看的版本）

### 为什么做这次重构

V5 方向正确，但复杂度过高（18 子类实体、17 项画像、35 种行为路径、7+1 指标、自动回测闭环），导致首版工期过长、调整成本高、不利于快速迭代。

### 重构的核心思路

**不是推翻 V5 重做极简版，而是"保留骨架、压缩上游、保住覆盖"。**

V5 的复杂度约 70% 集中在**指标上游**（实体分类、归因方法、画像体系、行为路径百科），而不是指标计算本身。所以正确的做法是：保留评分制框架（多指标打分 → 加权 → CBS Score → 异动推送），大幅压缩上游每一环。

### 压缩的具体位置与理由

| 压缩位置 | V5 规模 | V8 规模 | 为什么这么做 |
|---------|--------|--------|------------|
| 实体二级分类 | 18 子类 | 8 子类 | E 类（借贷/治理/稳定币）对首版核心场景覆盖增量极小 |
| 画像指标 | 17 项 + 3 层 16 种标签 | 5 项 + 1 标签 | 首版信号还没跑通，画像精度优化是过度工程化 |
| BMS 行为匹配分 | 5 维度对比 | 1 维度（仓位基线对比） | 1 维覆盖 80% 的"认真程度"判断 |
| 行为路径 | 35 种 | 19 种 | 删掉的是低频 / 低置信度路径，覆盖损失很小 |
| 计分指标 | 7+1 | 5 | 指标 6（结构性事件）拆分归入其他指标 + 独立推送；Perp 延后 |
| 实体归因 | 4 种自建方法 | 第三方标签 + 手动 | Arkham/Nansen 已覆盖主流实体 |
| 回测系统 | 自动三窗口 + 反馈闭环 | 人工记录 | 先让信号跑起来，再自动化优化 |

### 没有被压缩的部分（刻意保留）

| 保留项 | 为什么不能砍 |
|--------|------------|
| **评分制框架**（多指标 → 加权 → 总分 → 触发） | 这是模块二的"身份证"，砍了就不是 CBS |
| **LP 动态**（简化版 2 子维度） | 对 TRUMP 类热点和已持仓标的的流动性风险预警不可或缺 |
| **筹码集中度**（简化版） | 提供"存量视角"——谁在买/卖是流量，筹码分布是存量，两者不可替代 |
| **项目方行为** | 80% 需求是验证已有标的，项目方出货是最直接的风险信号 |
| **白名单 + 双触发模式** | 核心运行机制 |

### 最终效果

| 维度 | V5 | V8 |
|------|-----|-----|
| 整体复杂度 | 100% | **~35%（降低约 65%）** |
| 高价值场景覆盖 | 100% | **~80%** |
| 被砍掉的 20% 是什么 | — | 做市商精细分析、完整画像精度、自动回测闭环、Perp 修正 |
| 核心主场景（已有标的验证）受影响吗 | — | **不受影响** |

## 二、系统目标

构建一个持续运行的自动化系统，监控链上高质量资金实体的行为，从中识别资金异动信号，当信号强度达到阈值后推送给投研分析师，帮助团队捕获早期投资机会或风险预警。

**CBS 是注意力引擎五个模块之一，承担"资金面真相的最快通报者"角色**：
- 不是全市场扫描器
- 不是交易决策系统
- 是"用链上资金行为，验证或质疑团队的投研判断"

**重心分配**（基于团队基金的真实需求）：

| 场景 | 占比 | 说明 |
|---|---|---|
| 持续验证团队已建仓/正在研究的标的 | 80% | 核心主场景 |
| 链上实时热点（如 TRUMP 级别大热点）及此前未进入投研视角的大项目 | 20% | 补充发现 |

核心链路：

```
发现高质量实体 → 采集链上行为 → 构建简版画像
→ 持续监控异动 → 与画像基线对比 → 计算指标与评分
→ 达阈值推送通知
```

## 四、M1 — 实体发现与白名单管理

### 4.1 实体来源

| 来源 | 方式 | 执行频率 |
|---|---|---|
| Arkham Intelligence | 爬取已标记实体及其地址 | 每周增量 |
| Nansen Labels | 导入 Smart Money / Fund 标签地址 | 每周增量 |
| 手动导入 | 投研团队手动添加已知机构/鲸鱼地址 | 按需 |
| 模式 B 发现 | 跨模块触发时发现的"疑似高质量"新地址 | 按需 |

**V8 变化 vs V5**：去掉"链上溯源"（Gas Funder / 资金流聚类发现关联地址），延后到 P1。首版依赖第三方标签 + 手动。

去重逻辑：以链上地址为唯一标识，已存在则跳过。多个地址可归属同一实体。

### 4.2 实体归因（Entity Resolution）

**V8 变化 vs V5**：V5 定义了 4 种归因方法（Gas 来源分析、资金流聚类、时序行为聚类、合约工厂追踪）。每种都是独立技术项目，工程量大。

**首版处理**：直接使用 Arkham/Nansen 提供的已有实体-地址映射，辅以投研团队手动归因。自建归因作为 P2 的竞争力项目。

**为什么这么做**：Arkham/Nansen 已覆盖绝大部分主流实体，首版投入自建归因的性价比极低。

### 4.3 实体分类（一级 / 二级）

**4 大类 8 子类。** 以 entity_id 为唯一标识。同一实体对不同 Token 可持有不同角色（通过 entity_token_roles 表实现）。

| 一级 | 二级 | 定义 | 看到时优先怎么理解 | 核心关注行为 |
|---|---|---|---|---|
| **A 主动买方** | A1 机构买方 | 有明确机构背景、主动配置下注 | 看机构有没有真下场 | 首次买入某 Token；加仓行为；买入后质押/锁仓（最强看多增强） |
| | A2 知名个人/KOL | 身份公开、市场关注度高 | 注意"表演折扣"——但真金白银仍有参考 | 大额加仓（真金白银 vs 嘴上说说）；清仓（可能引发跟随者抛售） |
| | A3 匿名高质量买方 | 身份不公开但历史质量高 | 看真正做交易的人在干什么 | 首次参与（最高 Alpha 值）；多个 A3 同时买入同 Token（独立共振） |
| **B 潜在卖方** | B1 机构供给方 | 低成本筹码持有者 | 看低成本筹码会不会出来 | 解锁后第一步行为；冷→热钱包转移（减仓前兆）；解锁后长期不动（最强持有信号） |
| | B2 项目方/基金会/Treasury | 项目直接相关、影响供给 | 看项目自己有没有在散货 | 大额 Token 转出；回购自家 Token（看好）；向做市商转入 Token（做市/上所准备）；为自家 Token 添加 LP |
| **C 中介通道** | C1 做市商 | 库存管理、报价、对冲 | 常规行为过滤，异常行为高价值 | 撤出/新增做市；多做市商同向 |
| | C2 交易所体系 | 充值、冷钱包、归集 | 交易通道，不是观点表达者 | CEX 地址标记用于指标 4 计算 |
| **D 去噪排除** | D 噪音 | MEV/套利/Bot/羊毛/女巫/已知操纵者 | 直接过滤 | 不追踪。确保准确识别和过滤 |

**V8 变化 vs V5**：V5 为 5 大类 18 子类。变化如下：

| V5 子类 | V8 处理 | 理由 |
|---------|--------|------|
| A1/A3/B1/B2/C1 | **保留** | 核心分类 |
| A2 知名个人 | **保留**（从 V7 补回） | 真金白银操作仍有参考价值，配合 conviction 判断使用 |
| C2 交易所 | **保留** | CEX 地址标记是指标 4 的数据基础 |
| D1-D4 | **合并为 D** | 四个噪音子类的区分对首版信号无影响，统一过滤即可 |
| C3 桥/路由/聚合器/Solver | **删除子类，穿透处理** | 不需要独立分类，在 Event Layer 中直接穿透到原始 EOA |
| C4 LP/池子/流动性调度 | **删除子类，并入指标层** | LP 行为在指标 5（LP 动态）中直接处理 |
| E1-E4 (借贷/托管/治理/稳定币发行方) | **延后到 P1** | 对首版核心场景（已有标的验证）覆盖增量极小 |

**注意**：A 类（主动买方）虽然分类名称是"买方"，但系统同样监控其卖出行为。A 类实体的卖出/减仓/清仓是核心风险信号——"之前在买的聪明钱开始卖了"。

### 4.4 准入评级

硬性门槛，任一不满足则 status = rejected：

| 检查项 | 条件 | 数据来源 |
|---|---|---|
| 标签可信度 | 至少 1 个可靠来源标记 | Arkham/Nansen/手动 |
| 活跃度 | 近 90 天有交易记录 | 链上数据 |
| 规模门槛 | 管理资产估值 > [TUNABLE: $100K] | 持仓快照 |

### 4.5 白名单管理

- 达标实体写入 whitelist_entities 表，状态为 active
- 首版规模：500-1000 实体
- 复审机制：投研团队每月手动复审，淘汰 [TUNABLE: 90d] 无活动的实体
- 标签衰减：[TUNABLE: 90d] 无链上活动 → 降入 dormant

**V8 变化 vs V5**：去掉"底部 10% 自动进入 review"机制。首版白名单规模小（~1000），人工管理可行，不需要自动化复审增加系统复杂度。

## 五、M2 — 简版画像构建

### 5.1 为什么需要画像

分类告诉你"这个实体是谁"。画像告诉你"这个实体过去表现如何、这次行为对它来说是否异常"。

**画像不是首版的精度优化工具，而是指标计算的关键依赖**——没有 `avg_position_pct`，就无法判断一个实体这次操作是"重仓认真下注"还是"小额试探"。

### 5.2 画像构建流程

```
Step 1: 历史行为采集
  拉取该实体所有地址在过去 [TUNABLE: 90 天] 的链上事件
  → 通过 Event Layer 归类为买入/卖出

Step 2: 交易配对
  将同一 Token 的买入和卖出匹配为"完整交易"
  规则: 按时间顺序，先买先配。部分卖出按比例拆分
  未平仓的持仓标记为 open_position

Step 3: 逐笔计算
  每笔完整交易计算:
  - PnL% = (卖出均价 - 买入均价) / 买入均价
  - 持仓时间 = 卖出时间 - 买入时间
  - 仓位占比 = 买入金额 / 买入时该实体总持仓估值

Step 4: 聚合统计 → 生成 5 项画像指标（见 5.3）

Step 5: 标签生成 → is_recently_effective（见 5.4）

Step 6: 快照存储 → 每日 UTC 00:00 更新
```

### 5.3 5 项核心画像指标

| 指标 | 计算方式 | 用途 |
|---|---|---|
| `win_rate_90d` | 近 90 天完成交易的胜率（盈利交易数 / 总完成交易数）| 实体可信度 |
| `avg_pnl` | 近 90 天平均 PnL% | 盈利能力 |
| `avg_position_pct` | 近 90 天平均单笔仓位占比 | **指标 1 金额评分基线（conviction 判断的核心）** |
| `avg_hold_days` | 近 90 天平均持仓天数 | 持仓风格 |
| `last_active_at` | 最近链上活动时间 | 活跃度过滤 |

**V8 变化 vs V5**：V5 画像为 17 项指标。V8 从中提取了对首版信号计算贡献最大的 5 项。被去掉的 12 项（包括 profit_factor、max_position_pct、avg_trades_per_month、avg_entries_per_trade、avg_entry_position、event_proximity_rate、preferred_mcap_range、preferred_chain 等）全部在 P1 画像升级时恢复。

**为什么这 5 项就够**：
- `win_rate_90d` + `avg_pnl`：判断实体质量（这个人赚不赚钱）
- `avg_position_pct`：判断 conviction（这次操作对这个人来说认不认真）
- `avg_hold_days`：区分短线和中长线风格
- `last_active_at`：过滤僵尸实体

### 5.4 1 个动态标签

| 标签 | 触发条件 | 用途 |
|---|---|---|
| `is_recently_effective` | `win_rate_90d` > [TUNABLE: 55%] AND `last_active_at` < 30 天 | 信号推送时标注"该实体近期表现好" |

**V8 变化 vs V5**：V5 有 3 层共 16 种标签（A 层 6 种风格 + B 层 8 种执行路径 + C 层 3 种状态）。首版保留 C 层中最有用的 1 种。

### 5.5 Conviction 判断（V5 BMS 的简化替代）

V5 的 BMS（行为匹配分）通过 5 个维度对比（仓位、建仓方式、择时、标的匹配、历史类似操作）判断实体每次操作的认真程度。首版简化为 **1 个维度**：

```
conviction_ratio = 本次操作金额 / (该实体 avg_position_pct × 该实体当前总持仓估值)

conviction 分档:
  ratio > 2.0   → HEAVY (远超历史习惯的重仓操作)
  ratio 1.2~2.0 → HIGH  (高于历史平均)
  ratio 0.5~1.2 → NORMAL
  ratio < 0.5   → LOW   (远低于历史平均的试探性操作)
```

**为什么 1 维就够**："这个人花了多少比例的钱"是判断认真程度最直接、最不可伪造的维度。其他维度（择时、标的匹配、建仓方式）都是"锦上添花"，首版不需要。

### 5.6 画像冷启动

| 历史交易数 | 处理 |
|---|---|
| < 10 笔 | `confidence = low`，conviction 判断不可用，用全局市值分档 |
| 10-30 笔 | `confidence = medium`，画像可用但标注 |
| > 30 笔 | `confidence = high`，正常使用 |

### 5.7 画像更新机制

| 触发事件 | 更新内容 | 频率 |
|---|---|---|
| 每日快照 | 全量重算 5 项指标 + 标签 | 每日 UTC 00:00 |

**V8 变化 vs V5**：去掉实时增量更新和回测反馈更新。首版每日快照足够。

## 六、M3 — 链上行为监控（Event Layer）

### 6.1 数据采集

| 链 | 数据源 | 优先级 |
|---|---|---|
| Ethereum | Etherscan API + 备用 RPC | P0 |
| Base | Basescan API | P0 |
| Solana | Helius / Solscan API | P0 |
| Arbitrum | Arbiscan API | P1 |
| BSC | BSCScan API | P2 |

**V8 变化 vs V5**：

- V5 用 Allium/Goldsky 结构化数据。V8 首版改用 Etherscan 系列 API（更简单，免费层可用），降低数据依赖成本。
- Solana 保留 P0（链上热点标的大量在 Solana）。Arbitrum 降为 P1（当前链上资金活跃度不如 ETH/Base/Sol）。

### 6.2 行为识别（19 种路径）

V5 定义了 35 种行为路径。V8 保留 19 种（高频 + 高置信度 + 高覆盖贡献的路径）。

#### 6.2.1 真实买入（4 种）

| # | 路径 | 链上识别方式 | 置信度 |
|---|---|---|---|
| 1 | DEX Swap 买入 | Swap event: 主要资产流出 + 风险 Token 流入 | 1.0 |
| 2 | 聚合器路由买入 | 1inch/Paraswap 的 Swapped event → 穿透到发起交易的 EOA | 1.0 |
| 3 | 跨链后买入 | Bridge 到目标链 → 目标链 Swap 买入 | 1.0 |
| 4 | 交易场所对价推定 | 向 CEX 转入主要资产 → [TUNABLE: 24-72h] 内转出风险 Token → 金额匹配(±20%) | 0.6-0.8 |

不应计入买入：VC 轮分配、空投 Claim、LP Burn 收回双边资产、Bridge 合约到账（仅迁移）、被动收到的 ERC-20 Transfer（垃圾币空投宣传）。

**V8 变化 vs V5**：去掉 3 种低频低置信度路径（LP 隐含买入 0.5、LP 意图买入 0.2、OTC 对价买入 0.5），延后到 P1。

#### 6.2.2 真实卖出（4 种，与买入对称）

| # | 路径 | 置信度 |
|---|---|---|
| 1 | DEX Swap 卖出（风险 Token 流出 + 主要资产流入） | 1.0 |
| 2 | 聚合器路由卖出 | 1.0 |
| 3 | 跨链后卖出 | 1.0 |
| 4 | 交易场所对价推定卖出 | 0.6-0.8 |

不应计入卖出：LP Burn 收回双边资产、迁移至自有冷钱包、质押解除。

#### 6.2.3 迁移行为（6 种）

| # | 表现 | 信号含义 |
|---|---|---|
| 1 | 冷→热钱包转移 | 卖出前兆（高信号） |
| 2 | 热→冷钱包转移 | 长期存储意图 |
| 3 | CEX 入金 | 可能准备卖出 |
| 4 | CEX 出金 | 可能准备链上操作 |
| 5 | 同实体跨地址转移 | 内部调仓（识别后避免误报） |
| 6 | 向做市商转 Token | 做市合约启动（独立事件推送） |

**V8 变化 vs V5**：去掉"跨链迁移"和"做市商退回 Token"，延后到 P1。

#### 6.2.4 结构行为 / 过滤（5 种）

| # | 表现 | 处理 |
|---|---|---|
| 1 | Router/Aggregator 中转 | 穿透到发起交易的 EOA |
| 2 | Bridge 中转 | 穿透到原始发送者 |
| 3 | Solver 执行 | 穿透到订单发起者 |
| 4 | 做市商常规做市 | 基于 C1 标签过滤 |
| 5 | 闪电贷 | 过滤 |

**V8 变化 vs V5**：去掉"LP 全范围做市（仅计入指标 7）"和"做市商常规库存平衡"的独立路径。做市商常规行为统一通过 C1 标签过滤。

#### 6.2.5 噪音行为 — 丢弃

MEV/Sandwich、套利 Bot、女巫/空投猎人、尘埃攻击(<$1)、合约自动执行、测试交易。通过 D 类名单 + 行为模式匹配识别后全部丢弃。

### 6.3 Event Layer 处理流程

```
Step 1: 原始事件接收
  ← EVM: Transfer, Swap, Mint, Burn, Deposit, Withdraw
  ← Solana: SPL Transfer, DEX Swap

Step 2: D 类地址过滤
  黑名单匹配 + 行为模式匹配 (Sandwich/套利模式)
  命中 → 丢弃 | 未命中 → 继续

Step 3: 结构行为穿透
  Router/Bridge/Solver → 追踪到原始 EOA
  闪电贷 → 丢弃
  C1 常规做市 → 过滤

Step 4: 白名单匹配
  在白名单 → 继续精细分析
  不在白名单 → 仅计入指标 3（新参与实体发现）+ 指标 5（LP 全量统计）

Step 5: 行为分类（白名单地址）
  Swap → 真实买入/卖出
  Transfer to/from CEX → 迁移
  Transfer 同实体 → 迁移（内部调仓）
  向做市商 Transfer → 迁移（做市启动）

Step 6: Conviction 计算
  对白名单 A 类实体的买入/卖出事件:
  conviction_ratio = 操作金额 / (avg_position_pct × 当前总持仓估值)
  标记 HEAVY / HIGH / NORMAL / LOW

Step 7: 标准化事件输出
  {实体, Token, 行为类型, 金额, 置信度, conviction_label, 
   is_first_touch, 时间, 链}
```

**`is_first_touch` 标记规则**：
- 只标记**主动买入行为**（confirmed_buy / inferred_buy）产生的首次交互
- 被动收到的 ERC-20 Transfer（无对应主要资产流出）不计入
- 空投 Claim 事件明确排除

### 6.4 双触发运行模式

- **模式 A（白名单扫描，常驻）**：每小时扫描白名单全部地址 → Event Layer → 指标更新 → CBS Score → 异动检测
- **模式 B（跨模块响应，按需）**：其他模块通知 CBS 检查某 Token →
  1. 白名单维度：查询该 Token 相关实体的近期行为
  2. Token 维度：拉取全量大额交易，识别疑似高质量的非白名单地址 → 标记为"待入库观察"

## 七、M4 — 指标计算与信号引擎

### 7.1 核心设计：保留评分制框架

CBS 的核心设计是**评分制**：5 个指标各自打分 → 加权汇总 → CBS Score → 其中最强的少数场景可以单独触发推送。

每个指标输出有向值 [-100, +100]（标准化后），加权汇总得到 CBS Score。

**V8 变化 vs V5**：V5 为 7+1 指标。V8 调整为 5 指标：

| V5 指标 | V8 处理 | 理由 |
|---------|--------|------|
| 指标 1 净流入/流出 | **保留（I-1）** | 核心中的核心 |
| 指标 2 连续增持/减持天数 | **保留（I-2）** | 极低复杂度、高性价比 |
| 指标 3 参与动态 | **保留（I-3），简化为 2 子维度** | 多实体共振是最高置信度信号 |
| 指标 4 CEX 净流量 | **保留（I-4）** | 最成熟的链上信号之一 |
| 指标 5 持仓集中度 | **保留简化版（I-5），改为白名单持仓占比** | 提供不可替代的"存量视角" |
| 指标 6 结构性事件 | **取消独立计分** | 子事件拆分归入 I-1/I-4 + 独立推送 |
| 指标 7 LP 动态 | **保留简化版（I-LP），2 子维度** | 对热点标的和已持仓标的的流动性风险预警不可或缺 |
| Perp 修正项 | **延后 P2** | V5 自身已标注 Phase 2 |

### 7.2 指标体系（5 个计分指标）

#### 指标 I-1：高质量资金净流入/流出（权重 0.30）

**回答**："白名单资金对该 Token 的净方向是什么？"

```
计算:

Step 1: 累加白名单实体的净流入金额
  net_flow = Σ(买入金额 × 置信度 × conviction_multiplier) 
             - Σ(卖出金额 × 置信度 × conviction_multiplier)
  
  conviction_multiplier:
    HEAVY  = 1.5  (远超历史习惯的重仓,信号最强)
    HIGH   = 1.2  (高于历史平均)
    NORMAL = 1.0
    LOW    = 0.6  (试探性操作,参考价值低)

Step 2: 迁移前兆事件纳入（来自 V5 指标 6 的供给侧部分）
  冷→热转移: 该实体对该 Token 的持仓 × 0.3 × (-1) → 偏空
  大额 CEX 入金: 入金金额 × 0.5 × (-1) → 偏空

Step 3: 归一化
  使用 Token 的市值分档做基准（非 Z-score，更直观）:
  
  大盘 Token (FDV > $1B):
    |net_flow| > $10M → ±100
    $5M~10M → ±70
    $2M~5M → ±40
    $500K~2M → ±20
    < $500K → 0
  
  中盘 Token ($100M~$1B):
    > $3M → ±100, $1M~3M → ±70, $500K~1M → ±40, $100K~500K → ±20
  
  小盘 Token (< $100M):
    > $1M → ±100, $300K~1M → ±70, $100K~300K → ±40, $30K~100K → ±20

时间窗口: 分别计算 24h / 7d / 30d
  I-1 = 0.5 × I-1_24h + 0.3 × I-1_7d + 0.2 × I-1_30d
```

#### 指标 I-2：连续增持/减持天数（权重 0.15）

**回答**："方向持续了多久？"

```
计算:
  统计指标 1 每日净方向:
    如果当日 I-1_24h > 0 → 记为正向天
    如果当日 I-1_24h < 0 → 记为负向天
    如果当日 I-1_24h = 0 → 不计入

  连续天数:
    从今天往回看,连续同向天数(允许中间跳过无活动天)
    
  归一化:
    连续增持: 7天 → +70, 14天 → +100 (线性, 上限14天)
    连续减持: 7天 → -70, 14天 → -100
    方向翻转时重置

时间窗口: 实时计算（基于历史每日快照）
```

**V8 变化 vs V7 反馈**：反馈指出"初衷是连续天数越多则越强"。V8 采用简单直接的连续天数计数（允许跳过无活动天），而非 V7 的"主导方向比例"模式。更简单、更符合直觉。

#### 指标 I-3：多实体参与动态（权重 0.20）

**回答**："多少独立实体在参与？方向是否一致？"

```
子维度 3a: 新增参与实体数
  窗口内首次与该 Token 交互的白名单 A 类实体数
  (is_first_touch = true 的实体)
  
  每新增 1 个实体 → +15, 上限 +60

子维度 3b: 净方向比例
  (净买入 A 类实体数 - 净卖出 A 类实体数) / 总活跃 A 类实体数
  直接映射 [-100, +100]
  (100% 看多 = +100, 100% 看空 = -100)

综合:
  I-3 = 0.4 × f(3a) + 0.6 × f(3b)
  
时间窗口: 分别计算 24h / 7d
  I-3 = 0.6 × I-3_24h + 0.4 × I-3_7d
```

**V8 变化 vs V5**：V5 有 3 子维度（含覆盖率 3c）。V8 简化为 2 子维度，删除覆盖率（白名单总实体数作为分母意义有限）。

#### 指标 I-4：交易所净流量（权重 0.15）

**回答**："CEX 端的资金供需如何？"

```
计算:
  对白名单地址:
    net_cex_flow = 白名单 CEX 出金总额 - 白名单 CEX 入金总额
    正值 = 净提币(看多), 负值 = 净充值(看空)
  
  对全量地址 (可选增强):
    全量 CEX 余额变化 (如接入 CryptoQuant)
  
  归一化: 同 I-1 市值分档

时间窗口: 24h / 7d / 30d
  I-4 = 0.5 × I-4_24h + 0.3 × I-4_7d + 0.2 × I-4_30d
```

**V8 处理原 V5 指标 6 中的 CEX 部分**：V5 的"大额入所/出所"事件在指标 6 中单独处理。V8 将其统一纳入指标 4（CEX 净流量），避免重叠。

#### 指标 I-5：LP 动态 + 白名单持仓占比（权重 0.20）

**回答**："流动性和筹码结构有什么变化？"

这是 V8 相对 V5 / V7 的关键创新：将 V5 的指标 5（持仓集中度）和指标 7（LP 动态）的核心价值合并为一个"结构健康度"指标。

```
子维度 5a: LP 池子深度变化 (权重 0.5)
  监控主要 DEX 池的主资产余额变化
  
  快速增长 (24h 主资产增长 > 30%) → +100 (资金涌入,TRUMP 模式)
  稳步增长 (7d 增长 > 10%) → +50
  稳定 (变化 < ±10%) → 0
  稳步下降 (7d 下降 > 10%) → -50
  快速下降 (24h 下降 > 30%) → -100 (流动性撤退,风险预警)

子维度 5b: 异常 LP 事件检测 (权重 0.3)
  正向异常:
    项目方/大额地址新增 LP → +50 (护盘/看好信号)
    多个地址短时间加池 → +30
  
  负向异常:
    短时间多 LP 撤出 + 深度骤降 → -100 (极高风险)
    项目方单边注入 Token 不注主资产 → -50 (项目方靠市场提供买方流动性)
  
  无异常 → 0

子维度 5c: 白名单实体持仓占比变化 (权重 0.2)
  白名单 A 类实体持仓占 Token 流通量的百分比,取 7d 变化
  
  占比上升 > 2pp → +50 (高质量资金在聚集)
  占比稳定 → 0
  占比下降 > 2pp → -50 (高质量资金在撤离)
  
  数据来源: 白名单实体余额(已在 Event Layer 追踪) + Token 流通量(API)

I-5 = 0.5 × f(5a) + 0.3 × f(5b) + 0.2 × f(5c)

时间窗口: 7d / 30d
```

**为什么这么合并**：LP 动态和筹码集中度本质上都在回答"这个 Token 的结构健康吗"——前者从流动性角度，后者从筹码分布角度。合并后用 1 个指标覆盖 V5 的 2 个指标的核心价值，降低指标数但不损失覆盖。

**对 TRUMP 类热点标的的覆盖**：子维度 5a 直接捕获"池子主资产快速增长"（散户 FOMO 涌入），子维度 5b 捕获"项目方单边注入 Token"的异常模式。

### 7.3 CBS Score 计算

```
CBS_Score = W1×I-1 + W2×I-2 + W3×I-3 + W4×I-4 + W5×I-5

权重: W1=0.30, W2=0.15, W3=0.20, W4=0.15, W5=0.20

结果范围: [-100, +100]

语义解读:
  +60 ~ +100 → 强看多
  +20 ~ +60  → 温和看多
  -20 ~ +20  → 中性
  -60 ~ -20  → 温和看空
  -100 ~ -60 → 强看空
```

**V8 变化 vs V7**：

V7 采用"加法基础分 + 单向风险惩罚"的设计，有以下问题（基于反馈）：

1. **为什么只有风险惩罚没有利多加分？** — LP 增长、多实体集中加仓等利多行为也应该被体系捕获。V8 解决方案：利多和利空信号**对称地**反映在各指标的正负值中，不需要单独设置 bonus/penalty。正向 LP 变化在 I-5 中得到正分，反向得到负分——这比单向惩罚更合理。

2. **评分可分解性**：V8 保留了 V7 的优点——CBS Score 可完整分解为每个指标的贡献："CBS Score 71 = I-1 贡献 +25 + I-2 贡献 +12 + I-3 贡献 +18 + I-4 贡献 +8 + I-5 贡献 +8"。

### 7.4 独立事件推送（不计入 CBS Score）

部分高价值但低频的事件不适合纳入评分（频率太低会扭曲分数），但单次触发时必须推送给分析师。

| # | 事件 | 触发条件 | 说明 |
|---|---|---|---|
| **E-1** | 做市商撤出/新增做市 | 已标记 C1 做市商地址的 LP 操作异常 | 频率极低但单次价值极高 |
| **E-2** | 项目方向做市商转 Token | B2 → C1 大额 Transfer | 做市/上所准备信号 |
| **E-3** | 供给侧激活 | B1/B2 实体长期静默后首次异动（冷→热 / CEX 入金）| "沉睡的卖压正在醒来" |

**独立事件推送 vs 评分指标的区别**：
- **评分指标**（I-1 到 I-5）：持续计算，产出 CBS Score，反映 Token 的综合资金面状态
- **独立事件推送**（E-1 到 E-3）：事件触发型，不影响 CBS Score，但必须即时通知分析师

**V8 变化 vs V7**：V7 有 6 类独立事件（E-1 到 E-6）。V8 压缩为 3 类最高价值的事件，其余（E-4 池子快速增长、E-6 大额转移）已被 I-5 和 I-1 覆盖。

### 7.5 异动推送触发条件

| 推送类型 | 优先级 | 触发条件 |
|---------|--------|---------|
| **watchlist 风险预警** | P0 | watchlist 标的：CBS Score 24h 变化 ≥ 40 分（正或负） |
| **急性共振** | P0 | 24h 内 ≥ 3 个 A 类实体首次买入同一 Token + 合计 > $500K |
| **连续增持确认** | P1 | 连续增持 > [TUNABLE: 7] 天 |
| **A1 机构首次参与** | P1 | A1 机构实体首次买入某 Token |
| **独立事件** | P1 | E-1 / E-2 / E-3 触发 |

推送降噪：同一 Token 每小时最多 [TUNABLE: 3] 条推送。

### 7.6 异动推送 Payload 示例

```
CBS 异动报告 | $XYZ | 2026-05-28 14:32 UTC
触发: 急性共振 (3 个 A 类实体 24h 内首次买入)
```

## 十、边界条件与风险

| 场景 | 处理方式 |
|---|---|
| Fresh Wallet | 首版不追踪（自建归因延后），如 Arkham 已标记则纳入 |
| Router/Bridge 中转 | 穿透到原始 EOA |
| CEX 内部不可见 | 接受局限，只推测不确认 |
| 做市商常规噪音 | 基于 C1 标签过滤 |
| Token 无价格 | 不计入指标计算 |
| 代币改名 | 以 contract_address + chain 为键 |
| 画像冷启动 | < 10 笔 = low confidence，用全局分档 |
| 垃圾币空投宣传 | is_first_touch 只标记主动买入，被动 Transfer 排除 |

## 十五、待确认问题

1. **Nansen / Arkham API 实际成本** — 决定白名单种子库的构建速度
2. **历史数据回溯深度** — 简版画像 90 天 vs 180 天？影响数据采集成本
3. **CryptoQuant 是否接入** — 增强 I-4 的全量 CEX 数据，替代方案：Glassnode、自建 CEX 地址追踪
4. **跨模块接口规范** — 与 MTS/NDS/ECS/BAS 的 Score 格式统一
5. **链上数据成本** — Etherscan API 免费层是否够用，何时需要付费档
6. **Solana 数据源** — Helius vs Solscan，定价与稳定性比较
7. **LP 数据精度** — 简化版 LP 监控（池子余额级别）是否满足需求，还是需要 V3 Position 级别
