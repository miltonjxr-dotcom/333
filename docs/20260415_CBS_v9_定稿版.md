## 〇、版本说明

### 本版定位

本文档是模块二的**定稿文档**。经过 V5→V8 多轮迭代，主体分类、指标框架（I1-I7）、模式层定位、标签方向均已基本确定。本版不再发散，只做收敛：深化 I4-I7 打分细节、CBS 总分计算、标签-指标映射、模式层修正逻辑。

### 模块二定义

**模块二 = 资金面持续判断 + 时效性报警。**

| 场景 | 占比 | 说明 |
|------|------|------|
| 验证已持仓 / 在研究标的 | 80% | 核心主场景 |
| 发现新机会 / 新风险 | 20% | 补充发现 |

### 主脉络

```
白名单与分类 → 基线层(简版画像) → 行为识别(Event Layer)
→ 主体状态标准化 → I1-I7 指标计算
→ 模式识别与 CBS 总分修正 → 标签 / 推送 / 早报 / API 输出
```

| 术语 | 定义 |
|------|------|
| CBS | Capital Behavior Signals，资金行为信号，注意力引擎模块二 |

## 二、主体分类

### 2.1 分类体系

7 类主体。以 entity_id 为唯一标识。

| 代码 | 名称 | 定义 | 在指标中的角色 |
|------|------|------|---------------|
| **M** | 机构 | 有明确机构背景，主动配置下注 | → I1/I2/I3 |
| **A** | 匿名聪明钱 | 身份不公开但历史质量高 | → I1/I2/I3 |
| **I** | 个人/KOL | 身份公开，市场关注度高 | → I1/I2/I3（带 conviction 折扣） |
| **F** | 项目方/供给侧 | 项目方、Treasury、早期投资者、低成本筹码持有者 | → **I7 为主**，部分 LP 行为 → I5 |
| **MM** | 做市商 | 库存管理、报价、对冲 | → **I5** |
| **E** | 交易所 | 充值、冷钱包、归集 | 通道，不主计算。CEX 地址标记用于 I4 |
| **X** | 噪音 | MEV/套利/Bot/羊毛/女巫/已知操纵者 | 直接过滤 |

### 2.2 M/A/I 的核心关注行为

**虽然分类名称是"买方"，系统同时监控其卖出行为。**

| 类别 | 买入侧关注 | 卖出侧关注 |
|------|-----------|-----------|
| M 机构 | 首次买入某 Token；加仓；买入后质押/锁仓 | 减仓；清仓；冷→热转移后卖出 |
| A 匿名聪明钱 | 首次参与（最高 Alpha）；多 A 同时买入（共振） | 获利了结；方向翻转 |
| I 个人/KOL | 大额加仓（真金白银 vs 嘴上说说） | 清仓（可能引发跟随者抛售） |

### 2.3 F 类的核心关注行为

| 行为 | 信号含义 | 归入指标 |
|------|---------|---------|
| F→CEX 大额转入 | 准备出货 | **I7**（负向事件） |
| 冷→热钱包转移 | 出货前兆 | **I7**（负向事件） |
| F 向做市商转 Token | 做市/上所准备 | **I7**（中性偏正事件） |
| F 回购自家 Token | 看好信号 | **I7**（正向事件） |
| F 添加 LP（双边） | 护盘 | **I5**（正向修正） |
| F 单边注入 Token 到 LP | 靠市场提供买方流动性 | **I5**（负向修正） |
| 解锁后长期不动 | 最强持有信号 | **I7**（缺省 = 不触发 = 中性） |

### 2.4 MM 类的核心关注行为

| 行为 | 信号含义 | 归入指标 |
|------|---------|---------|
| 常规做市 | 噪音，过滤 | 不计入 |
| 撤出做市 | 极高风险预警 | **I5**（负向） |
| 新增做市 | 正向结构改善 | **I5**（正向） |
| 多做市商同向操作 | 信息不对称 | **I5**（放大） |

### 2.5 准入评级

| 检查项 | 条件 |
|--------|------|
| 标签可信度 | 至少 1 个可靠来源标记（Arkham/Nansen/手动） |
| 活跃度 | 近 90 天有交易记录 |
| 规模门槛 | 管理资产估值 > $100K |

## 三、基线层（简版画像）

### 3.1 5 项核心指标

| 指标 | 计算 | 用途 |
|------|------|------|
| `win_rate_90d` | 近 90 天完成交易胜率 | 实体可信度 |
| `avg_pnl` | 近 90 天平均 PnL% | 盈利能力 |
| `avg_position_pct` | 近 90 天平均单笔仓位占比 | **conviction 判断基线** |
| `avg_hold_days` | 近 90 天平均持仓天数 | 风格判断 |
| `last_active_at` | 最近活动时间 | 活跃度过滤 |

### 3.2 conviction 计算

```
conviction_ratio = 本次操作金额 / (avg_position_pct × 当前总持仓估值)

HEAVY:  ratio > 2.0   → 乘数 1.5
HIGH:   ratio 1.2~2.0 → 乘数 1.2
NORMAL: ratio 0.5~1.2 → 乘数 1.0
LOW:    ratio < 0.5   → 乘数 0.6
```

### 3.3 动态标签

| 标签 | 条件 |
|------|------|
| `is_recently_effective` | win_rate_90d > 55% AND last_active_at < 30 天 |

### 3.4 画像更新

每日 UTC 00:00 全量快照。首版不做实时增量更新。

## 五、I1-I7 指标体系

### 5.0 总览

| 指标 | 职责 | 量纲 | 主要输入主体 | 权重 |
|------|------|------|------------|------|
| **I1** | 净流入流出（方向 + 力度） | [-100, +100] | M / A / I | **0.25** |
| **I2** | 连续性（验证 I1 方向是否持续） | [0, 100] | 跟随 I1 | **0.10** |
| **I3** | 共振 / 分歧 | [-100, +100] | M / A / I | **0.20** |
| **I4** | 交易所库存趋势 | [-100, +100] | E（全量 CEX） | **0.15** |
| **I5** | LP / 流动性健康度 | [-100, +100] | MM + F(LP部分) + 全量 | **0.10** |
| **I6** | 持仓集中度变化 | [-100, +100] | 全量 + 白名单 | **0.10** |
| **I7** | 关键实体转移风险 | [-100, +100] | F | **0.10** |

**总权重 = 1.00**

### 5.1 I1：净流入流出

**职责**：方向 + 力度。这是系统锚点。

```
计算:

net_flow = Σ(M/A/I 买入金额 × 置信度 × conviction_mult) 
         - Σ(M/A/I 卖出金额 × 置信度 × conviction_mult)

归一化: 基于 Token 市值分档

  大盘 (FDV > $1B):
    |net_flow| > $10M → ±100,  $5M~10M → ±70,
    $2M~5M → ±40,  $500K~2M → ±20,  < $500K → 0
  
  中盘 ($100M~$1B):
    > $3M → ±100,  $1M~3M → ±70,  $500K~1M → ±40,  $100K~500K → ±20
  
  小盘 (< $100M):
    > $1M → ±100,  $300K~1M → ±70,  $100K~300K → ±40,  $30K~100K → ±20

时间窗口加权:
  I1 = 0.5 × I1_24h + 0.3 × I1_7d + 0.2 × I1_30d
```

### 5.2 I2：连续性

**职责**：验证 I1 方向是否持续。不独立表达方向——方向借 I1。

```
量纲: [0, 100]（无负值；方向已由 I1 决定）

计算:
  从今天往回看 I1 的每日快照:
    I1_24h > 0 → 记为正向天
    I1_24h < 0 → 记为负向天
    I1_24h = 0 → 跳过不计
  
  streak_days = 连续同向天数（允许跳过无活动天）
  
  归一化:
    1 天 → 7
    7 天 → 50
    14 天 → 100
    (线性插值, 上限 14 天)

乘法应用到总分:
  I2 不直接加到 CBS_raw。
  实际作用: CBS 总分中 I1 的贡献 = I1 × (1 + I2/200)
  
  含义:
    streak = 0 天 → I1 贡献不变
    streak = 7 天 → I1 贡献 ×1.25
    streak = 14 天 → I1 贡献 ×1.50

为什么这么做:
  I2 的存在意义就是"给 I1 加持续性加成"。
  如果 I2 独立加到总分，会与 I1 方向重复计分。
  用乘法作用于 I1，让连续性增强 I1 的信号强度，但不产生独立方向分。
```

### 5.3 I3：共振 / 分歧

**职责**：验证 I1 的支持度与反对度。保留负值——分歧/反向共振是有效信息。

```
量纲: [-100, +100]

计算:

  对该 Token 在窗口内所有活跃的白名单 M/A/I 实体:
    
    支持方权重 = Σ(净买入实体的类别权重)
    反对方权重 = Σ(净卖出实体的类别权重)
    
    类别权重:
      M 机构   = 3
      A 匿名   = 2
      I 个人   = 1
    
    raw_I3 = (支持方权重 - 反对方权重) / (支持方权重 + 反对方权重) × 100
    
    特别加分: 窗口内有 is_first_touch 的实体
      每个 first_touch 实体额外 +5 (正向) / -5 (反向)
      上限 ±20

时间窗口:
  I3 = 0.6 × I3_24h + 0.4 × I3_7d
  
示例:
  24h 内: 2 个 M 买入 + 1 个 A 买入 + 1 个 A 卖出
  支持 = 3+3+2 = 8, 反对 = 2
  raw = (8-2)/(8+2) × 100 = +60
  
  24h 内: 1 个 M 买入 + 3 个 A 卖出
  支持 = 3, 反对 = 2+2+2 = 6
  raw = (3-6)/(3+6) × 100 = -33 （分歧信号）
```

### 5.4 I4：交易所库存趋势

**职责**：市场级 CEX 库存变化。**不混 F 类具体行为**（F→CEX 的归因在 I7）。

```
量纲: [-100, +100]
正值 = CEX 库存下降 = 提币看多
负值 = CEX 库存上升 = 充值看空

数据源优先级:
  1. CryptoQuant API (Exchange Reserve) — 最准确
  2. 自建: 监控已标记 E 类地址的 Token 余额变化 — 备选

计算:
  reserve_change_pct = (当前 CEX 余额 - N天前余额) / N天前余额

  归一化 (按变化百分比):
    < -10%     → +100 (大量提币,强看多)
    -10% ~ -5% → +70
    -5% ~ -2%  → +40
    -2% ~ +2%  → 0 (中性)
    +2% ~ +5%  → -40
    +5% ~ +10% → -70
    > +10%     → -100 (大量充值,强看空)

时间窗口:
  I4 = 0.6 × I4_7d + 0.4 × I4_14d

为什么只看全量不看 F 具体行为:
  I4 的职责是反映"市场级供需趋势"。
  如果把 F→CEX 混入 I4，会导致:
    1. 与 I7(关键实体转移) 重复计分
    2. 单一 F 大额操作扭曲市场级视角
  F 的具体 CEX 操作归 I7，I4 只看全量交易所余额走势。
```

### 5.5 I5：LP / 流动性健康度

**职责**：流动性结构是否健康。

```
量纲: [-100, +100]

子维度 5a: 池子深度变化 (权重 0.6)
  监控主要 DEX 池的主资产余额变化
  
  24h 主资产增长 > 50%    → +100 (资金涌入,TRUMP 模式)
  7d 增长 > 20%           → +60
  稳定 (7d 变化 < ±10%)  → 0
  7d 下降 > 20%          → -60
  24h 下降 > 50%          → -100 (流动性撤退)
  
  (中间值线性插值)

子维度 5b: 关键 LP 行为 (权重 0.4)
  正向:
    MM 新增做市 → +60
    F 双边添加 LP → +40
    多 MM 同向加深 → +80
  
  负向:
    MM 撤出做市 → -80
    多 LP 短时间集中撤出 + 深度骤降 → -100
    F 单边注入 Token 不注主资产 → -40
  
  无事件 → 0

I5 = 0.6 × f(5a) + 0.4 × f(5b)

时间窗口: 7d 为主
```

### 5.6 I6：持仓集中度变化

**职责**：筹码结构是否恶化/改善。

```
量纲: [-100, +100]

计算:
  简化版: 不做全量三层分析，只做白名单维度

  whitelist_a_holding_pct = 白名单 M/A 类实体持仓 / Token 流通量
  delta_7d = 当前占比 - 7 天前占比
  delta_30d = 当前占比 - 30 天前占比

  归一化:
    delta > +5pp  → +100
    delta +2~+5pp → +60
    delta +0.5~+2pp → +30
    delta -0.5~+0.5pp → 0
    delta -2~-0.5pp → -30
    delta -5~-2pp → -60
    delta < -5pp  → -100
  
  I6 = 0.6 × f(delta_7d) + 0.4 × f(delta_30d)

数据来源:
  白名单实体余额 — Event Layer 已追踪
  Token 流通量 — CoinGecko / DexScreener API
```

### 5.7 I7：关键实体转移风险

**职责**：F 类（项目方/供给侧）的高解释力事件。这是**事件型指标**——默认为 0，只在特定事件触发时产出分数，并随时间衰减。

```
量纲: [-100, +100]

事件触发与评分:

  负向事件 (供给风险):
    F→CEX 大额转入 (> 流通量 0.5% 或 > $1M)     → -80
    F 冷→热大额转移 (> 流通量 0.3%)              → -50
    B1 解锁后首次向 CEX 转入                      → -70
    
  正向事件 (信心信号):
    F 回购自家 Token (> $200K)                    → +60
    F 向 MM 转 Token (做市启动)                   → +30
    解锁后 7+ 天无异动                            → +40
    
  中性 (无事件): 0

多事件叠加:
  同一 Token 上多个 F 类事件同时触发,取代数相加,
  上限: ±100

衰减机制:
  事件触发后, I7 分数随时间线性衰减:
    触发当日: 100% 分值
    +3d:     70%
    +7d:     40%
    +14d:    10%
    +14d 后: 归零

  衰减的含义:
    "项目方 3 天前向 CEX 转了一大笔"比
    "项目方 14 天前转了一笔"更紧迫。
    但如果 14 天后仍未在 CEX 卖出,风险已大幅下降。

  新事件覆盖:
    如果衰减期内出现新的同向事件, 取较大绝对值重新开始衰减
    如果出现反向事件 (如转入 CEX 后又回购), 代数相加

为什么 I7 不包含 M/A/I 的行为:
  M/A/I 的买卖已在 I1 计入。如果 I7 也包含,会双重计分。
  I7 专职 F 类——这些实体的行为不在 I1 中反映(F 不是"买方"),
  但对 Token 的供给结构有决定性影响。
```

## 六、CBS 总分计算

### 6.1 计算公式

```
━━━ CBS Score 计算 (v9) ━━━

Step 1: I1-I7 各自独立计算 (见第五节)

Step 2: I2 作用于 I1 (乘法增强,不独立进入加权)
  I1_effective = I1 × (1 + I2/200)
  clamp(I1_effective, -100, +100)

Step 3: 加权求和
  CBS_raw = 0.25 × I1_effective
          + 0.20 × I3
          + 0.15 × I4
          + 0.10 × I5
          + 0.10 × I6
          + 0.10 × I7

  注: I2 的权重(0.10)通过 Step 2 间接作用于 I1,
      不再单独出现在加权公式中。
      等效: I1 的实际权重 = 0.25 × (1 + I2/200),
            范围 0.25 ~ 0.375。
      这意味着当连续性满档(14天)时,I1 的影响力最大增加 50%。

Step 4: 模式层修正 (见第七节)
  CBS_Score = clamp(CBS_raw + pattern_adjustment, -100, +100)
  pattern_adjustment 范围: [-10, +10]

━━━ 分数可分解性 ━━━

推送时必须展示:
  CBS Score +65 = I1(含连续性加成) +22 | I3 +16 | I4 +10 
                  | I5 +6 | I6 +5 | I7 +6 | 模式修正 +0
```

### 6.2 I1/I2/I3 去重问题的处理

**问题**：I1（净方向）、I2（连续性）、I3（共振）都基于 M/A/I 的买卖行为，是否存在重复计分？

**回答**：三者虽然输入数据相同（M/A/I 的买卖事件），但回答的问题完全不同：

| 指标 | 回答的问题 | 数学上做了什么 |
|------|-----------|--------------|
| I1 | 钱往哪个方向流？流了多少？ | 金额加权净值 |
| I2 | 这个方向持续了多久？ | 时间序列上的连续计数 |
| I3 | 多少独立决策者同意这个方向？ | 实体计数 + 方向一致性 |

它们之间的关系是**互补验证**，而非重复：
- I1 高 + I2 低 + I3 低 = "一个大户刚买了一笔"（置信度低）
- I1 高 + I2 高 + I3 高 = "多个实体持续同向操作"（置信度极高）
- I1 高 + I2 高 + I3 负 = "有人在买，但也有人在卖"（分歧信号）

**I2 不独立进入加权，而是乘法作用于 I1**——这从结构上消除了方向维度的重复计分。I3 独立进入加权是合理的，因为"实体数量一致性"是 I1 无法替代的维度。

### 6.3 I7 过强问题的处理

I7 是事件型指标，单次触发可达 ±80~100。如果不设上限，一个 F→CEX 事件就能主导整个 CBS Score。

**处理**：
1. I7 权重仅 0.10 → 即使 I7 = -100，对总分的直接影响也只有 -10 分
2. 衰减机制确保 I7 不会"永远挂着高分"
3. 但 I7 会通过**模式层**产生额外影响（见第七节）——当 I7 与 I1/I3 反向时，模式层会触发"供给侧出货"标签并做小幅总分修正

---

## 七、模式层

### 7.1 定位

**模式层不重算指标。** 它做两件事：
1. 组合解释：基于 I1-I7 的组合判断当前属于哪种"模式"
2. 小幅总分修正：在 CBS_raw 上做 [-10, +10] 范围的微调

### 7.2 模式识别规则

| 模式 | 主读指标 | 触发条件 | 修正量 |
|------|---------|---------|--------|
| **结构性建仓** | I1>40 AND I2>50 AND I3>30 | 多实体持续同向买入 | +5 |
| **聪明钱撤退** | I1<-30 AND I3<-20 | 多实体同向卖出 | -5 |
| **供给侧出货** | I7<-40 AND I1>0 | F 在出货但买方还在 | -8 |
| **流动性撤退** | I5<-50 | LP 大规模撤出 | -5 |
| **买方 vs 供给侧分歧** | I1>30 AND I7<-30 | 买方看好但 F 在跑 | -5（降低总分置信度） |
| **机构 vs 聪明钱分歧** | I3 中 M 与 A 方向相反 | 机构和匿名聪明钱不一致 | 0（仅标签，不修正） |
| **多机构急性共振** | I3_24h 中 M 类 ≥3 同向 | 短时间多机构涌入 | +8 |
| **新机构进场** | I3 中 M 类 first_touch ≥2 | 之前没买过的机构开始买 | +5 |

**修正叠加规则**：
- 多个模式可同时触发
- 正向修正上限 +10，负向修正上限 -10
- 如果正向和负向同时触发，代数相加（但仍受 ±10 上限约束）

### 7.3 模式层在系统中的位置

```
I1-I7 各自计算完毕 (纯指标层,客观)
    ↓
CBS_raw = 加权求和
    ↓
模式层: 读取 I1-I7 的组合 → 判断模式 → 小幅修正 ±10
    ↓
CBS_Score = clamp(CBS_raw + adjustment, -100, +100)
    ↓
同时输出: 主标签 + 状态标签 + 修饰标签
```

## 八、标签体系

### 8.1 三层标签

#### 主模式标签（核心 6 + 发现 2）

基于模式层输出。**一个 Token 同时最多 2 个主标签。**

| 标签 | 主读指标 | 触发逻辑 |
|------|---------|---------|
| **结构性建仓** | I1 + I2 + I3 | I1>40, I2>50, I3>30 |
| **聪明钱撤退** | I1 + I3 | I1<-30, I3<-20 |
| **供给侧出货** | I7 + I1 | I7<-40，无论 I1 正负 |
| **流动性撤退** | I5 | I5<-50 |
| **买方 vs 供给侧分歧** | I1 + I7 | I1>30 AND I7<-30 |
| **机构 vs 聪明钱分歧** | I3 内部 | I3 中 M 子分与 A 子分方向相反 |
| **多机构急性共振** | I3 | 24h 内 M 类 ≥3 实体首次同向买入 |
| **新机构进场** | I3 | M 类 first_touch ≥2 |

#### 状态标签（4 种，互斥）

基于 CBS_Score 区间。每个 Token 只有 1 个状态标签。

| 标签 | 条件 |
|------|------|
| 资金面平静 | \|CBS_Score\| < 15 |
| 轻度偏多 | CBS_Score 15~40 |
| 轻度偏空 | CBS_Score -40~-15 |
| 方向不明 | I3 接近 0 且 I1 与 I7 方向相反 |

#### 修饰标签（5 种，可叠加）

| 标签 | 条件 |
|------|------|
| 重仓 | 窗口内出现 conviction = HEAVY 的事件 |
| 持续性 | I2 > 50（连续 7+ 天） |
| 多方 | I3 中 3+ 类别同向 |
| CEX 端存疑 | I4 与 I1 方向相反 |
| KOL 反向 | I 类实体与 M/A 类方向相反 |
