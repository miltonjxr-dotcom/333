# CBS 模块二：V5 结构性重构评审

> 版本: v3.0 | 日期: 2026-04-15
> 方法: 不推翻 V5，而是从 V5 中逐层评审"保留 / 简化 / 延后"，保留评分制骨架
> 目标: 复杂度 −66%，高价值场景覆盖 ~80%

---

## 零、本轮分析的核心修正

前两轮分析有两个偏差需要修正：

**偏差 1：把 V5 的"评分制指标体系"重构为"4 类信号系统"——方向有价值，但偏离了模块二的设计初衷。**

模块二的核心设计是**打分制**：多个指标各自打分 → 加权汇总 → CBS Score → 其中最强的少数指标可以单独触发推送。这不是一个"信号分类系统"，而是一个"多维度评分 + 异动触发系统"。前两轮把它改造成 4 类独立信号，虽然提炼出了最重要的业务场景，但丢失了评分制的框架价值——**多个维度协同产出一个综合判断**。

正确做法：保留评分制骨架，但大幅减少喂给评分制的上游复杂度。

**偏差 2：对 LP、筹码集中度、项目方行为的处理过于粗暴（直接删除或延后），低估了它们对"已有标的验证"的覆盖贡献。**

80% 的需求是"验证已有标的"。对已持仓的价值型标的来说：
- **项目方/Treasury 行为**：直接关系供给风险，不可省略
- **LP 变化**：对 TRUMP 这类大热点，池子结构直接反映市场情绪和风险（如"项目方只注 Token、主资产全靠散户"就是极高信息量的信号）；对价值型标的，深度骤变也是关键预警
- **筹码集中度**：虽然全量分层模型过重，但简化版的"鲸鱼层占比变化"对验证有直接参考价值

正确做法：不机械删除，而是评估每一项能否以较低复杂度保留其核心覆盖价值。

---

## 一、统一的评估原则

对 V5 的每一项能力，不问"能不能删"，而问：

| 判断维度 | 问题 |
|---------|------|
| **覆盖贡献** | 这项能力覆盖的是高频主场景还是边缘场景？ |
| **复杂度代价** | 它带来的工程/数据/维护复杂度有多大？ |
| **可简化程度** | 能否在保留核心覆盖的前提下，大幅降低实现复杂度？ |
| **替代性** | 删掉后，其他能力能否部分覆盖它的场景？ |

一句话判断标准：**保留对 80% 核心覆盖贡献大的能力；简化复杂度高但覆盖不可替代的能力；延后主要服务低频/增强场景的能力。**

---

## 二、V5 的问题不在指标层，而在指标上游

这是一个关键认知：V5 的 7 个指标本身的计算逻辑并不复杂（加权求和、Z-score 归一化、窗口聚合），真正重的是**喂给指标的上游链路**：

```
┌─────────────────────────────────────────────────────────────────┐
│  V5 复杂度分布                                                    │
│                                                                   │
│  上游 (占复杂度 ~70%)              指标层 (占 ~15%)  产出层 (~15%)  │
│  ┌───────────────────────┐        ┌──────────┐     ┌──────────┐  │
│  │ 18 子类实体分类        │        │          │     │          │  │
│  │ 4 种归因方法           │        │ 7+1 指标  │     │ CBS Score│  │
│  │ 17 维画像 + 3 层标签   │───────▶│ 各自打分  │────▶│ 异动推送 │  │
│  │ 5 维 BMS 对比          │        │ [-100,100]│     │ Dashboard│  │
│  │ 35 种行为路径          │        │          │     │ 跨模块API│  │
│  │ LP/做市商全量分析      │        └──────────┘     └──────────┘  │
│  │ 自动回测闭环           │                                       │
│  └───────────────────────┘                                       │
└─────────────────────────────────────────────────────────────────┘
```

**所以正确的精简策略是：保留指标层骨架（评分制 + 总分 + 触发），大幅压缩上游的每一环。**

## 三、V5 六层能力逐层评审

### 第一层：模块骨架（必须完整保留）

这些是模块二的"身份证"，删了就不是 CBS 了：

| 骨架组件 | V5 原设计 | 首版保留方式 | 复杂度变化 |
|---------|----------|------------|-----------|
| 评分制框架 | 7 指标各自打分 → 加权 → CBS Score | 保留，但指标数从 7 压到 5 | 无变化（框架本身不复杂） |
| 总分输出 | CBS Score [-100, +100] | 保留 | 无变化 |
| 强信号独立触发 | 7 种推送条件 | 保留最高价值的 4-5 种 | 略简化 |
| 白名单机制 | 实体发现 + 准入评级 + 复审 | 保留，简化复审频率 | 略简化 |
| 异动推送 | Slack/飞书 + Dashboard | 保留 | 无变化 |
| 跨模块查询 API | 模式 B | 保留 | 无变化 |
| 双触发模式 | 模式 A（白名单扫描）+ 模式 B（按需查询）| 保留 | 无变化 |

---

### 第二层：实体体系（大幅简化）

| V5 组件 | V5 规模 | 覆盖贡献 | 复杂度 | 首版处理 | 理由 |
|---------|--------|---------|--------|---------|------|
| **一级分类（5 类）** | A/B/C/D/E | 极高 | 低 | **保留 A/B/C/D 四类** | E 类（借贷/治理/稳定币）对首版核心场景覆盖增量有限 |
| **二级分类（18 子类）** | A1-E4 完整 | 中 | 高 | **简化为 ~8 子类** | 保留：A1 机构 / A3 匿名高手 / B1 供给方 / B2 项目方 / C1 做市商 / C2 交易所 / D（合并为一类噪音）。删除：A2 KOL（表演折扣问题使其信号质量不稳定）、C3 桥路由（纯穿透，不需要独立分类）、C4 LP（并入指标层直接处理）、E1-E4（延后） |
| **实体归因（4 种方法）** | Gas/资金流/时序/合约追踪 | 中 | 极高 | **延后。首版用第三方标签 + 手动** | 4 种方法每一种都是独立技术项目，但 Arkham/Nansen 已覆盖大部分主流实体 |
| **准入评级** | 3 项硬性门槛 | 高 | 低 | **保留原设计** | 本身就很简洁 |
| **白名单管理** | active/review/dormant + 月度复审 | 中 | 中 | **简化**：去掉月度自动复审，改为投研手动管理 | 首版白名单规模小（~1000-2000），人工管理可行 |

**实体层复杂度变化**: 18 子类 → 8 子类，归因 4 方法 → 0（第三方），复审自动化 → 手动。**复杂度约 −65%**。

### 第三层：画像体系（从"完整建模"降级为"最小可信度层"）

这是 V5 最重的单一模块。V5 画像包含：17 项指标 → 3 层 16 种标签 → 5 维 BMS → 每日快照 → 增量更新 → 冷启动规则。

| V5 画像组件 | 覆盖贡献 | 复杂度 | 首版处理 | 理由 |
|------------|---------|--------|---------|------|
| **胜率指标（3 项）** | 高——直接决定实体可信度 | 低 | **保留 win_rate_all + win_rate_90d** | 两项足够区分"高质量"和"一般" |
| **盈亏指标（4 项）** | 中 | 低 | **保留 avg_pnl + profit_factor** | 2 项足够反映盈利能力 |
| **持仓指标（4 项）** | 中——用于 conviction 判断 | 中 | **保留 avg_position_pct** | 1 项足够判断"本次操作认不认真" |
| **节奏指标（2 项）** | 低 | 低 | **延后** | 对首版覆盖贡献小 |
| **择时指标（2 项）** | 低 | 中 | **延后** | 需要 30d 高低点数据，收益不高 |
| **偏好指标（2 项）** | 中——能力圈判断 | 中 | **延后** | 需要足够历史才有意义 |
| **A 层风格标签（6 种）** | 低 | 中 | **延后** | 分析师可通过原始指标自行判断 |
| **B 层执行路径标签（8 种）** | 低 | 中 | **延后** | 主要服务 BMS，BMS 已简化 |
| **C 层状态标签（3 种）** | 中 | 低 | **保留 1 种**："近期有效"（win_rate_90d > 55%）| 1 个布尔标签足以区分"最近手感好不好" |
| **BMS 行为匹配分（5 维对比）** | 高——核心精髓 | 高 | **简化为 1 维**：仓位占比 vs 历史均值 | 1 维覆盖 80% 的"认真程度"判断 |
| **画像更新闭环** | 中 | 高 | **简化**：仅每日快照，去掉实时增量更新和回测反馈 | 降低系统复杂度 |
| **冷启动规则** | 低 | 低 | **保留简化版**：< 10 笔 = 未评级，≥ 10 笔 = 可用 | 逻辑简单 |

**首版画像 = 5 项核心指标 + 1 个状态标签 + 1 维 conviction + 每日快照。**

**画像层复杂度变化**: 17 指标 → 5 指标，16 标签 → 1 标签，5 维 BMS → 1 维。**复杂度约 −75%**。

### 第五层：指标计算与信号引擎（保留骨架，调整指标集）

这是核心决策：保留几个指标？以下逐一评审 V5 的 7+1 指标：

#### 指标 1：高质量资金净流入/流出（V5 权重 0.25）

| 维度 | 评估 |
|------|------|
| **覆盖的核心场景** | "聪明钱在买还是在卖？" — 所有场景的基础 |
| **对 80% 验证需求的贡献** | **极高。** 这是回答"有没有高质量资金跟你站同一边"的直接指标 |
| **对 20% 发现需求的贡献** | 高。附加 `is_first_touch` 标记后，自然覆盖新领域发现 |
| **复杂度** | 中 — 需要 Event Layer 喂入 + 实体质量加权 |
| **可简化部分** | 归一化可从 Z-score 简化为分档映射（绝对金额 × 质量分 → 直接分档） |
| **结论** | **必须保留。权重可维持 0.25** |

#### 指标 2：连续增持/减持天数（V5 权重 0.15）

| 维度 | 评估 |
|------|------|
| **覆盖的核心场景** | "资金方向持续了多久？" — 趋势持续性验证 |
| **对验证需求的贡献** | 高。连续 7 天增持 vs 单日脉冲买入，投研含义完全不同 |
| **复杂度** | **极低。** 只需追踪指标 1 的每日正负号连续性 |
| **可简化部分** | 几乎无需简化，本身就是最简指标 |
| **结论** | **必须保留。** 复杂度极低但覆盖贡献高——这正是"高性价比"指标 |

#### 指标 3：高质量资金参与动态（V5 权重 0.15）

| 维度 | 评估 |
|------|------|
| **覆盖的核心场景** | "多少独立实体在参与？方向是否一致？" — 多主体共振检测 |
| **对验证需求的贡献** | **极高。** 多实体独立共振是最高置信度的验证信号 |
| **对发现需求的贡献** | **极高。** 多个实体首次共同参与某 Token = 最强发现信号 |
| **复杂度** | 中 — 3 个子维度（新增实体数、净方向比例、覆盖率） |
| **可简化部分** | 子维度从 3 简化为 2：保留 3a（新增参与实体数）和 3b（净方向比例），删除 3c（覆盖率 — 白名单总实体数作为分母意义有限） |
| **结论** | **必须保留。简化为 2 子维度** |

#### 指标 4：交易所净流量（V5 权重 0.15）

| 维度 | 评估 |
|------|------|
| **覆盖的核心场景** | "CEX 端的资金供需如何？" |
| **对验证需求的贡献** | 高。已持仓标的的 Token 大量流入 CEX = 卖压预警 |
| **复杂度** | **低。** CEX 地址已被广泛标记，Transfer 监控即可 |
| **可简化部分** | 几乎无需简化 |
| **与指标 1 的重叠** | 部分重叠（白名单实体的 CEX 操作同时影响指标 1 和指标 4），但 V5 已有不重叠规则（金额归指标 4，实体维度归指标 6）。首版可进一步简化：白名单实体的 CEX 操作计入指标 1，指标 4 只关注全量 CEX 流量（不限白名单） |
| **结论** | **保留。** 复杂度低、覆盖贡献高，且是最成熟的链上信号之一 |

#### 指标 5：持仓集中度变化（V5 权重 0.10）

这是本轮需要深入评估的指标。

| 维度 | 评估 |
|------|------|
| **V5 完整设计** | 三层分层持仓（鲸鱼/中等/零售），每层叠加实体分类标签，每日快照 |
| **对验证需求的贡献** | **中高。** 对已持仓标的："鲸鱼（A 类）占比持续上升"是正向验证，"B 类鲸鱼占比上升"是风险信号。这不能被指标 1-4 完全替代——指标 1-4 看的是"流量"（谁在买/卖），指标 5 看的是"存量"（筹码分布在改善还是恶化） |
| **对发现需求的贡献** | 低 |
| **完整实现的复杂度** | **高。** 需要全量 Token 持有者数据（全量 Transfer 历史重建余额），数据量大、成本高 |
| **能否简化** | **能。** 不需要三层分层模型。可大幅简化为：|

**首版简化方案**:

放弃全量三层分层持仓分析，改为**白名单实体持仓占比变化**：
- 仅追踪白名单实体（已有数据，无新增成本）对某 Token 的持仓占比变化
- 计算维度：白名单 A 类实体持仓占流通量 % 的 7d/30d 变化
- 不需要全量 Token 持有者数据——只需要白名单实体的余额（已在 Event Layer 中追踪）+ Token 流通量（DexScreener/CoinGecko API）
- 输出：简化为"白名单占比上升/稳定/下降"三档

**简化后复杂度**: 从"全量持仓重建 + 三层分层"降为"白名单余额聚合 / Token 流通量"。**复杂度降低 ~80%，但保留了"存量视角"的核心覆盖价值。**

| **结论** | **保留简化版。** 不做三层全量分析，只做"白名单实体持仓占比变化"。权重可降至 0.05-0.08 |

#### 指标 6：结构性资金事件（V5 权重 0.10）

| 维度 | 评估 |
|------|------|
| **V5 完整设计** | 双层输出（量化评分 + 事件流），涵盖：大额入所/出所、跨链迁移、冷→热、做市商区间/库存/撤出/新增/同向/间转移 |
| **问题** | 这个指标内部承载了太多异质内容，从"冷→热转移"到"做市商库存偏移"跨度极大 |
| **对验证需求的贡献** | 做市商部分：中高但低频；供给侧/迁移部分：高 |
| **首版处理** | **拆分并重新归属** |

首版对指标 6 的拆分方案：

| V5 指标 6 子事件 | 首版归属 | 理由 |
|-----------------|---------|------|
| 大额入所/出所 | → 指标 4（CEX 净流量）| 与 CEX 流量天然同类 |
| 冷→热转移 | → 指标 1（作为方向性行为的前兆事件，负向加权）| 直接反映卖出意图 |
| 做市商撤出/新增 | → **独立高优先级事件推送**（不计入评分） | 频率太低不适合计分，但单次价值极高 |
| 做市商区间/库存/同向 | → **延后至 P1** | 复杂度高，首版信号价值被做市商标签质量瓶颈限制 |
| 跨链迁移 | → **延后** | 对首版覆盖贡献低 |
| 做市商间筹码转移 | → **延后** | 方向不明，需人工判断 |

**结论：首版不保留指标 6 作为独立计分指标。其中高价值子事件被吸收到指标 1 和指标 4 中，做市商撤出/新增保留为独立推送事件。**

#### 指标 7：LP 行为与流动性动态（V5 权重 0.10）

这是本轮需要深入分析的另一个关键指标。

| 维度 | 评估 |
|------|------|
| **V5 完整设计** | 4 子维度：池子深度变化、撤池/加池检测、流动性集中度、流动性迁移。全量 LP 数据 |
| **对验证需求的贡献** | **中高——取决于标的类型** |
| **对热点标的（如 TRUMP）** | **极高。** TRUMP 案例表明：项目方只注 Token 不注主资产、散户提供全部主资产买入——这个池子结构本身就是极强的市场情绪信号。LP 变化速度直接反映资金进出速率 |
| **对价值型标的** | **中。** 深度骤降 = 风险预警（流动性撤退）；深度持续增厚 = 正向验证 |
| **完整实现复杂度** | **高。** V3 Position NFT 追踪、Pool 事件监听、4 个子维度各自计算 |

**深入分析：LP 的核心覆盖价值到底在哪？**

对基金来说，LP 的信号价值不在于精细的流动性集中度分析或 V2→V3 迁移追踪，而在于以下 2-3 个高解释力现象：

| LP 现象 | 信号含义 | 对基金的价值 | 技术实现难度 |
|---------|---------|------------|------------|
| **池子主资产快速增长**（散户涌入提供主资产） | 市场 FOMO 情绪高涨，资金容量在扩大 | 对热点标的：极高（TRUMP 模式）。对价值标的：中 | **中低** — 监控池子的主资产余额变化即可（Pool 合约 balanceOf） |
| **池子深度快速下降**（多 LP 撤出） | 流动性撤退，可能预示重大风险 | **高** — 对所有标的类型都是风险预警 | **中低** — 监控 LP Remove 事件 + 池子余额 |
| **项目方/大额 LP 单边注入 Token**（只加 Token 不加主资产） | 项目方在提供卖压，靠市场提供买方流动性 | **高** — 直接反映项目方行为和市场结构 | **中** — 需识别大额 LP Mint 事件 + 判断注入比例 |
| 流动性集中度变化（Top5 LP 占比） | 流动性结构脆弱性 | 中 | 高 — 需 V3 Position 追踪 |
| 流动性迁移（V2→V3，链 A→链 B） | 生态偏好变化 | 低 | 高 |

**首版简化方案**:

保留 LP 作为一个计分指标，但从 4 子维度简化为 **2 个高解释力子维度**：

- **7a（简化版）: 池子深度变化方向** — 监控主要 DEX 池的主资产余额变化速度。快速增长 = 正向（资金涌入），快速下降 = 负向（流动性撤退）
- **7b（简化版）: 异常 LP 行为检测** — 短时间内多 LP 撤出 + 深度骤降 = 高风险事件触发

去掉 7c（流动性集中度）和 7d（流动性迁移）。

**关键决策：项目方单边注入 Token 的情况**——这属于 LP 行为和项目方行为（指标 6 中 B2 部分）的交叉。首版归入 LP 指标（7b 的子场景），通过 LP Mint 事件中的 Token 比例异常来识别。

**简化后复杂度**: 4 子维度 → 2 子维度，去掉 V3 Position 精细追踪，只做池子级别的余额/事件监控。**复杂度降低 ~60%，但保留了对热点标的和风险预警最关键的覆盖。**

| **结论** | **保留简化版。** 从 4 子维度压为 2 个高解释力维度。权重可降至 0.08 |

## 四、关于热点/meme 标的兼容性的专项分析

你明确指出 meme 不是不抓——TRUMP 这种大热点必须参与。那首版系统对此类标的的兼容性如何？

| 能力 | 对 TRUMP 类大热点的覆盖 |
|------|----------------------|
| **I-1 净流入** | **完全覆盖。** 高质量资金大规模涌入 = 强正向信号 |
| **I-3 参与动态** | **完全覆盖。** 多个实体首次同时参与 = 最强发现信号。`is_first_touch` 标记在此类场景下最活跃 |
| **I-7 LP 简化版** | **关键覆盖。** TRUMP 的核心链上特征之一就是池子结构——"项目方只注 Token、散户提供主资产"。简化版的 7a（池子主资产快速增长）直接捕获这个信号 |
| **I-2 连续天数** | 对 meme 类标的价值较低（行情可能只持续数天），但不影响 |
| **I-4 CEX 净流量** | 覆盖。大热点通常伴随 CEX 大量出金（提币到链上参与） |
| **I-5 持仓占比** | 对 meme 类标的价值较低，但不影响总分 |

**结论**: 首版 5 指标体系对 TRUMP 类大热点的覆盖是充分的。I-1（资金涌入）+ I-3（多实体首次共振）+ I-7（池子结构）三者联动，足以在链上产生强信号。

**关于垃圾币项目方向知名实体地址空投代币进行宣传的问题**:

这类行为在 `is_first_touch` 判断中确实会产生误报——实体的地址被动收到 Token 转入，不代表该实体主动参与。

**首版过滤方案**: `is_first_touch` 只标记**主动买入行为**（confirmed_buy / inferred_buy），不标记被动收到的 Transfer。具体而言：
- 只有通过 DEX Swap / 聚合器路由 / 跨链后 Swap 这三种高置信度买入路径产生的首次交互才标记为 first_touch
- 单纯的 ERC-20 Transfer 入账（没有对应的主要资产流出）不计入 first_touch
- 空投 Claim 事件明确排除

## 五、项目方行为的专项处理

你强调"项目方的相关举动同样重要"。确认保留，具体归属如下：

| 推送触发条件 | 7 种 | 5 种 + 2 种独立事件 | −0%（覆盖实际增加） |
| 回测系统 | 自动三窗口+闭环 | 人工记录 | −95% |
| **整体复杂度** | 100% | **~34%** | **−66%** |
| **高价值场景覆盖** | 100% | **~80%** | −20%（主要损失在做市商精细分析和 Perp） |

## 九、覆盖损失分析：被砍掉的 ~20% 是什么？

| 被砍的能力 | 损失的场景 | 影响评估 | 恢复时间 |
|-----------|----------|---------|---------|
| 做市商完整行为分析 | 做市商区间移动、库存偏移、自营交易、多 MM 关联分析 | **中** — 但做市商撤出/新增作为独立事件保留，最高价值场景未丢 | P1 |
| 完整三层画像 | 风格判断（事件驱动型 vs 趋势配置型）、执行路径分析 | **低** — 分析师可通过 5 项核心画像指标自行判断 | P1 |
| BMS 精细对比 | 择时匹配、能力圈判断、历史类似操作胜率 | **中低** — 仓位 conviction 已覆盖最核心维度 | P1 |
| LP 精细分析（集中度、迁移） | V3 Position 追踪、跨链 LP 迁移 | **低** — 首版 LP 已保留深度变化和异常检测 | P1 |
| Perp 修正 | 永续合约仓位对现货信号的增强/削弱 | **低** — V5 也标注为 Phase 2 | P2 |
| 自建实体归因 | 自动发现新的地址-实体关联 | **中** — 但第三方已覆盖主流实体 | P2 |
| 自动回测闭环 | 信号质量自动评估和参数自适应 | **低** — 首版人工评估足够 | P1 |

**关键判断**: 被砍掉的 20% 几乎不影响"已有标的验证"（80% 主场景），主要影响的是系统的"精度优化"和"自动化程度"。这些恰好是首版跑通后再补充的最佳候选。

## 十、最终判断

> **首版不是把模块二做成简陋版，而是把 V5 从"全栈完整版"收缩为"高价值主场景优先版"。保留评分制骨架和 5 个核心指标（资金净方向、连续天数、参与动态、CEX 净流量、LP 动态）+ 简化版持仓占比，把复杂度主要从画像深度、行为路径百科、做市商全覆盖和自动回测闭环上压掉。LP 和筹码集中度不删除但简化为高解释力版本，项目方行为完整保留。从而在复杂度下降约 66% 的情况下，保住约 80% 的高价值场景覆盖——尤其是"已有标的验证"这个绝对主场景不受影响。**
